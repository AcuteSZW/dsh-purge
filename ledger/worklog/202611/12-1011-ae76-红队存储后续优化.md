## Process

- `lib/redteam/store-core.js#addAttackFile`：target slug 后加入原始 target SHA-1 短摘要目录；同 target 复用旧 path，不同 target 共享 legacy path 时迁移到隔离目录并保留另一记录文件。`scripts/test-attack-file-path-collision.mjs` 验证 `http://host:80` 与 `host` 同名内容隔离、legacy共享路径迁移与输入校验。
- `lib/redteam/poc-file-transaction.js` 集成 `savePoc`/`updatePoc`/`deletePoc`：同目录临时文件+备份、DB主表与 FTS SQLite transaction、失败回滚与文件恢复；删除仅清理 pocs 根内未引用的普通文件和空直属目录，不递归删除。
- `lib/redteam/poc-file-transaction.js` 与 `store-core.js`：POC 文件改动通过 SQLite journal 与业务/FTS 行同事务提交；恢复在 `BEGIN IMMEDIATE` 下校验 journal 路径位于 pocs 根并幂等应用；提交后 finalize 失败明确抛 `POC_FILE_FINALIZE_FAILED` 且 `committed=true`、保留 journal 供下次恢复。无文件 POC 的 DB-only 写入不创建 journal；delete 操作类型独立于 file path，null path 不触发文件 I/O。
- POC 子进程矩阵覆盖 create/overwrite 的 after-stage、commit-pending、after-commit，以及 delete 的 after-tombstone-commit；重复恢复、共享 path 双 row、外部 final/temp journal 拒绝、恢复失败不缓存 DB handle、DB-only POC 删除与 finalize 失败恢复均有断言。新增 committed final-leaf symlink 拒绝且外部 sentinel 不变、save 与 markPocUsed 竞争保留 hit_count/used_on 的回归。commit 前崩溃产生的无 journal `.tmp/.bak` 故意保留，不扫描删除活动 writer 的暂存文件。
- POC 并发回归 `scripts/test-poc-file-multiprocess.mjs` PASS：旧 journal schema 两进程迁移、6 recovery worker、共享引用删除/更新、同记录双删严格验证一次 deleted/另一次 not-found、sole-owner 删除/更新终态一致。`scripts/test-poc-cleanup-race.mjs` PASS：生产 API 的 SQLite 写锁协调、旧 path 清理、共享引用与 Windows 大小写别名引用保留。
- `scripts/test-attack-file-path-collision.mjs` 在 Windows Node v26.13.0 下 PASS：不同 raw target 隔离、预占冲突不覆盖、按卷大小写行为检查大小写别名、Windows 分隔符别名、设备保留名、尾随点、legacy 冲突重隔离及输入校验；POSIX 实机未运行。
